# Issue 99 public-release safety audit

## Scope and handling policy

This audit covers the tracked working tree and Git objects reachable through
`--all` before the repository is made public. It classifies documentation,
PowerShell entry points, generated Ludii trials, and Git identity metadata
separately.

The audit does not reproduce personal email addresses, credential candidates,
or secret-like values. Findings use counts and classifications only. The
repository remains private, and this work does not change its visibility.

## Portable Ludii paths

The initial inventory found user-specific Ludii JAR paths in 12 Markdown files
and as defaults in 15 PowerShell scripts. Commit `cab852d` replaced Markdown
examples with `LUDII_JAR` / `$env:LUDII_JAR` and changed each script default to
the `LUDII_JAR` environment variable. Scripts that always require Ludii now
fail before experiment work when neither source supplies an existing file.
The Issue 68 analysis checks the JAR only when `-RefreshReplay` is requested.

Verification after that commit found:

- zero user-specific absolute paths in tracked Markdown and PowerShell files;
- zero PowerShell parser errors in the affected scripts;
- all 14 unconditional entry points rejected a missing JAR with the documented
  error;
- the environment-variable fallback resolved and validated its supplied path;
- the conditional Issue 68 check rejected a missing refresh JAR; and
- shell examples use the literal variable name `$LUDII_JAR` without Markdown
  escaping.

## Generated trial inventory

There are 3,046 tracked `.trl` files. Every file records an absolute `game=`
path generated by Ludii. Two machine-path shapes occur: 1,863 Windows-generated
trials and 1,183 macOS-generated trials. The paths identify a local checkout and
local user segment, but contain no credential, private attachment, or secret.

`TrialReplayAudit.java` performs a read-only check using an explicitly supplied
game definition. It loads the saved match record, matches every recorded
decision against a currently legal move, applies it, and compares move and turn
counts. For completed trials it also compares the natural end, winner, and end
type. It accepts intentionally partial evidence only when all recorded moves are
legal and the replay remains partial.

One representative was checked from each distinct trial source family:

| Source family | Board configuration | Result |
| --- | --- | --- |
| Legacy saved trials | 4x4 | Complete replay passed |
| Issues 11, 30, and 32 | 4x4 | Complete replay passed |
| Issue 35 | 4x4 | Intentional partial replay passed |
| Issue 47 | 4x4 | Complete replay passed |
| Issue 62 | 3x3 | Complete replay passed |
| Issue 82 | 3x3 | Complete replay passed |
| Issues 56, 58, and 60 | 6x6 | Complete replay passed |
| Issue 73 | 7x7 | Complete replay passed |
| Issue 77 | 7x7, 84 pieces per player | Complete replay passed with the historical experimental definition |

The macOS-generated representatives replayed on Windows while their recorded
checkout paths did not exist. This confirms that the repository replay flow
uses the explicitly supplied game definition rather than requiring the absolute
`game=` header to resolve.

Issue 77 records a game hash produced while the 84/96-piece experimental options
were present, but its recorded Git commit predates those worktree changes. The
current game definition also no longer contains those options. The representative
trial replayed with the later historical definition containing the same option,
but an exact clean-commit reconstruction of the recorded generation hash was not
available. This is a pre-existing provenance limitation; the trial and its
recorded artifacts are preserved unchanged.

## Trial hash and provenance impact

Representative hash checks established the following:

- Issue 35 source locks match the committed trial after LF normalization;
- Issue 47 and Issue 82 validation hashes match after LF normalization;
- Issue 83 source locks match after LF normalization;
- the documented Issue 73 trial-hash mismatch remains reproducible; and
- Issue 77 matches both its checkout-byte hash and canonical LF hash while
  retaining the Issue 73 source hash and mismatch disposition.

Known downstream evidence includes four unique Issue 35 source-trial locks,
199 Issue 47 validation records, 250 Issue 73 manifest rows, 750 Issue 77
manifest rows, 303 Issue 82 validation records, and 597 Issue 83 locked games.
These sets overlap and are not an additive count. Changing only the `game=` line
changes the trial bytes and would invalidate raw or canonical hashes across
these provenance chains.

The trial headers contain local usernames but no information that is judged
unacceptable for publication. Because rewriting them would alter experiment
evidence and its hash graph without removing a credential or private attachment,
all 3,046 trials are intentionally retained unchanged.

## Git identity disposition

At audit time, reachable history was scanned through all refs exposed by
`git --all`. The scanned author and committer metadata each classify as 59
noreply records, 58 personal-address records, and one local-host-address record.

Historical personal and local-host identities are intentionally retained. A
history rewrite would change every descendant commit identifier and require
coordinated replacement of all branches for no game or experiment benefit. No
rewrite or force-push is part of this issue. The current repository configuration
uses a GitHub noreply address, and future commits must continue to use a noreply
address.

## Secret and machine-local scan

The final tracked-file scan found:

- no private-key blocks;
- no recognized GitHub, OpenAI, or AWS token prefixes;
- no password, API-key, access-token, or client-secret assignments matching the
  audit patterns;
- no user-specific absolute paths outside the intentionally retained trials;
  and
- one historical temporary diagnostic-path record, containing no user identity
  or attached dump/log data, retained as experiment failure provenance.

The reachable-history patch scan found no commit matching the private-key or
recognized token-prefix patterns. Machine-specific paths occur in 34 commits,
as expected from the historical documentation, scripts, and generated trials.
There are no tags at the time of this audit.

This is a pattern-based safety review rather than a proof that arbitrary encoded
data cannot contain a secret. It covers tracked files and commits reachable from
local and remote refs exposed by `git --all`; unreachable objects, external
attachments, and services outside the repository are not inspected.

## Scope confirmation

bytes, analysis outputs, experiment conclusions, repository visibility, or Git
history. Issue 98 may resume after review of this audit and the Issue 99 changes.
